Rekurze a memoizace

by Jiří Znamenáček

1

Úvod

Jak jsme viděli v kapitole o rekurzi, je rekurze sice často elegantní způsob algoritmizace problému, ale ve stejnou chvíli neskutečně náročný na systémové zdroje (a často dokonce ani v reálném čase nedopočítatelný). Naštěstí však existují způsoby, jak rekurzivní algoritmy zrychlit. Mezi ně patří mimo jiné:

  • memoizace (aneb dynamické programování shora dolů);
  • dynamické programování (zdola nahoru).

Memoizace

Princip memoizace je tak jednoduchý, až to skoro bolí:

Každou spočítanou hodnotu pro dané vstupy si uložíme pro pozdější použití.

Jelikož – jak jsme viděli – se v průběhu rekurzivního výpočtu často řeší stejné zadání na několika různých místech, můžeme si ušetřit (až nečekaně!) výrazné množství času.

3

Příklad – faktoriál

Ideálním kandidátem pro použití v rámci memoizace v Python'u je datová struktura slovník – jejími klíči totiž mohou být n-tice, čímž se indexování vstupních parametrů do volání funkce významně zjednodušuje. Pro případ faktoriálu by program mohl vypadat třebas takto: 

# slovník zapamatovaných hodnot
fakt = {}

# upravená funkce pro výpočet faktoriálu
def faktorial_s_memoizaci(n):
    # Nepočítali jsme už žádanou hodnotu?
    try:
        return fakt[n]
    # Ne, ještě ne:
    except KeyError:
        if n == 0:
            return 1
        else:
            # ..spočítejme ji
            val = n * faktorial_s_memoizaci(n-1)
            # ..a nyní už ji jako známou uložme a vraťme
            fakt[n] = val
            return val

Pár poznámek

Externí slovník je obzvláště výhodný, pokud uvedenou funkci budete volat vícekrát. Dokonce mohou snadno nastat situace, kdy bude mít smysl takto spočítaný slovník uložit na disk (v Python'u viz moduly pickle nebo shelve) a používat ho (a průběžně doplňovat) během delší doby.

Jinak samozřejmě i „pouhé“ použití slovníku uvnitř rekurzivní funkce (v Python'u pomocí výchozích hodnot parametrů funkcí) ji neuvěřitelně zrychlí – opakující se zadání jsou ve stromu výpočtu pravidlem*.

Dynamické programování

Podle té které definice je dynamické programování vlastně nadmnožinou memoizace (jak jsem ostatně naznačil už na prvním slajdu):

Úkolem dynamického programování je využít možnosti rozložení úlohy na (v nějakém smyslu) jednodušší podúlohy stejného typu a v pozdějším výpočtu využít výsledků těchto jednodušších podúloh.

Přitom se dá postupovat dvěma různými způsoby:

  • zhora dolů – počítat úlohu postupně od zadání a mezivýsledky si ukládat pro pozdější použití (aneb klasická memoizace);
    📝
    Postupovat na stromu výpočtu tedy od kořene stromu (zadání úlohy) ke koncovým listům (koncové body rekurze).
  • zdola nahoru – počítat úlohu od nejjednodušších částí postupně směrem ke složitějším za použití již takto spočítaných jednodušších mezivýsledků.
    📝
    Z hlediska stromu výpočtu tedy naopak začít u koncových listů (kotvy rekurze) a postupně pokračovat směrem nahoru, až se dostaneme ke vstupu požadovanému zadáním.

Příklad – fibonacci

N-tý člen Fibonacciho posloupnosti počítaný metodou zdola nahoru by se dal v Python'u napsat třeba takto: 

    def fibonacci(n):
        if n == 0:
            return 0
        elif n == 1:
            return 1
        else:
            n2, n1 = 0, 1
            for x in range(n-1):
                n1, n2 = n1 + n2, n1
            return n1

Vlastně je to stejný algoritmus, jen opačně a bez jakéhokoliv rekurzivního volání – veškerou „magii“ tu nahrazuje smyčka for-in a případné dotazy na konečné případy řeší rozhodování pomocí if-elif-else.

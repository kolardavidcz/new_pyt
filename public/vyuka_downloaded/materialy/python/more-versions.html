Vícero Python'ů na jednom systému

by Jiří Znamenáček

1

Úvod

Vzhledem k dichotomii mezi trojkovou a dvojkovou řadou Python'u se vám velmi pravděpodobně stane, že budete:

  • pracovat na systému, kde je nainstalováno více různých verzí Python'u;
  • používat pro různé (nebo dokonce i stejné) projekty různé verze Python'u.

Proto je velmi důležité vědět, jak volat/použít právě ten Python, který zrovna potřebujete.

2

Linux – „python“

Na Linuxu je to většinou docela jednoduché* – každá verze Python'u má přiřazenu svoji vlastní pojmenovanou binárku. Největší zádrhel se schovává většinou jenom v tom, která z verzí je základní, tedy který Python se zavolá na příkaz python.

📝
* Pomíjím teď zcela fakt, že Linux měl pro systémový Python použít nějaký úplně jiný název (třebas python-system nebo tak něco) a byli bychom všech dnešních problémů ušetřeni. Mimochodem – Python nainstalovaný na Windows se vůbec jako systémový hlásit nemusí.

Jsou distribuce (např. Arch Linux), které už leta letoucí jako základní poskytují zásadně Python trojkový, takže na příkaz python se zavolá právě on. Většina distribucí však stále-pořád-ještě jako základní má Python dvojkový, takže trojkový se musí volat python3 (a často ještě nejdřív i doinstalovat).

3

Linux – „#!“

Uděláte-li pythoní skript spustitelným a vybavíte-li ho příslušnou hlavičkou (tzv. shebangem), použije se na jeho spuštění verze Python'u zde uvedená.

Platí ovšem úplně stejné omezení jako v předchozím případě – neurčíte-li verzi přesně pomocí čísla, tedy použijete pouze obyčejné python, zavolá se příslušná systémová.

📝
Nejhorší je to při přenášení skriptů mezi systémy – zatímco u vás může python volat poslední trojkovou binárku, u někoho jiného jako na potvoru spustí dvojkovou, na to vemte jed…
4

Windows – „#!“

Celkem šikovné chování shebangu z Linuxu kopírují windowsí instalace Python'u 3.3+ – s nimi se totiž do systému přidá spouštěč Python'u v podobě programu py.exe, který slouží k dohledání a zavolání nejvhodnější verze Python'u pro daný skript.

Číslo verze můžete předat na příkazové řádce (např. py -2.6 skript.py apod.) nebo právě v shebangové hlavičce skriptu. Nicméně rozeznávané hlavičky (nepočítáme-li čísla verzí Python'u) jsou jen a právě následující čtyři:

  • #!/usr/bin/env python
  • #!/usr/bin/python
  • #!/usr/local/bin/python
  • #! python
📝
A z praktických důvodů tam všude budete chtít psát python3.
5

Windows – „python“

S předchozím úzce souvisí chování skriptů, u nichž shebang není předepsán. Ve Windows jsou totiž všechny soubory jaksi automaticky spustitelné – když odentrujete/dvojkliknete (nejen) pythoní skript, pokusí se Windows najít program, který na něj zavolat. A zde nás čeká překvapení:

Máte-li nainstalovaný dohromady dvojkový i trojkový Python, tak i při vybrání trojkového jako výchozího se v tomto případě zavolá Python dvojkový!
📝
Ale samozřejmě pouze v případě, že byl při instalaci vybrán jako systémový. V opačném případě Windows jednoduše nebudou vědět, čím mají uvedený soubor zpracovat.

Uvedené chování bylo zřejmě (bohužel) vybráno s ohledem na běžné uživatele a rozšířenost dvojkových skriptů – když uživatel neví, co přesně chce, tak chce nejspíš dvojku… Naštěstí pro nás se to dá přepsat – stačí zavést proměnnou prostředí PY_PYTHON s hodnotou 3.

📝
Jen na to zase nezapomeňte, když budete skripty někomu předávat. Správně – a plně! – zapsaný shebang je nejjistější.

PS: Vývoj se pomalu přeci jen děje – od verze Python'u 3.6 je uvedené chování již vypnuté (alespoň pro spouštěč py.exe; příkaz python stále zavolá dvojku, pokud je naistalována jako systémová). Ale pochopitelně ne všude budete mít k dispozici tuhle nebo novější, takže veškeré uvedené připomínky platí i nadále.

6

Poznámky

Mimochodem – máte-li například více dvojkových Python'ů, na příkaz python2 se zavolá ten poslední. Což je bohudík aspoň celkem logické. Nicméně shrňme si to všechno dohromady:

Máte-li nainstalovány například Python'y 3.4.4 a 2.7.11, pak při použití hlavičky #!/usr/bin/env python (důležitý je tady ten samotný python na konci) se stejně zavolá Python 2.7.11, i když byla verze 3.4.4 vybrána jako hlavní. Jelikož to téměř určitě není očekávané chování, napravit ho můžete několika způsoby:

  1. změňte hlavičku na #!/usr/bin/env python3 ;
  2. nastavte proměnnou prostředí PY_PYTHON na hodnotu 3;
  3. volejte skript jako py -3 skript.py .

Druhý bod je nejsnažší pro vlastní práci, první bod je nejlepší při přenášení skriptů mezi systémy.

Třetí bod vypadá jako z nouze ctnost, ale jelikož zadání parametru spouštěče zvítězí nad případnou hlavičkou uvnitř skriptu, může se někdy také pěkně hodit.

7

PS: Poznámka pro Mac

Používáte-li nějaký přístroj s operačním systémem MacOS, sedíte v podstatě u nejpromyšlenějšího GUI pro unixový operační systém (historie MacOS X sahá až k BSD). Nicméně narozdíl od ostatních Unixů – a Linuxů – co Bůh Steve Jobs neschválil, to neučiníte.

Podobně jako v Linuxech je v MacOS přítomen systémový Python (a to zhusta ve dvojkové verzi), na který ovšem narozdíl od Linuxů nemáte právo vůbec sahat. Což je mimochodem dobře. Chcete-li tudíž pod MacOS provozovat nějaký svůj jiný Python (či dokonce Pythony), nezbyde vám nic jiného, než na to krásné a promyšlené GUI zapomenout a naučit se používat příkazovou řádku – moc jiných možností, než nainstalovat balíčkovací systém Homebrew a s jeho pomocí pak Python, totiž nemáte.

📝
Nebo můžete rovnou nainstalovat Condu. Ale příkazové řádce stejně neutečete ^_~

PS: Aby bylo jasno – pokud se nebojíte příkazové řádky (pod MacOS pravda trochu oxymoron), jste v mnohem lepší situaci než pod Linuxem, kde si můžete levou zadní rozvrtat systém, aniž byste o tom měli vůbec tušení. (Nehledě na to, že poslední inkarnace Linuxů s GUI padají snad víc, než kdy vůbec padaly Windows…)

📝
PPS: Pokud už máte od Applu notebook, pořiďte si od něj i všechno ostatní (mobil, televizi…) a zapomeňte, že existují i jiné systémy. Ušetříte si spoustu problémů.

Třídy a objekty v Python'u

by Jiří Znamenáček

1

Zavedení třídy

Zcela v duchu úvodu můžeme nejjednodušší třídu vyrobit jako zobecnění pojmenované n-tice. Narozdíl od n-tice však u třídy můžeme měnit hodnoty jejích prvků: 

>>> class MyClass:
...     a, b, c = 1, 2, 3
... 
>>> MyClass
<class '__main__.MyClass'>

>>> MyClass.a
1
>>> MyClass.a = 'ahoj'
>>> MyClass.a
'ahoj'

Tím jsme získali jeden pojmenovaný objekt, který umožňuje přístup ke svým prvkům pomocí tečkové notace (nebo jinými slovy – zavedli jsme nový jmenný prostor). To jsme si zase tak moc nepomohli...

2

Alias na třídu

...a přiřazení jiného jména třídě to samozřejmě nijak nevylepší: 

>>> mc = MyClass
>>> mc
<class '__main__.MyClass'>

>>> MyClass.a
1
>>> mc.a
1

# Tam..
>>> MyClass.a = 'ahoj'
>>> MyClass.a
'ahoj'
>>> mc.a
'ahoj'

# ..i zpět to samozřejmě funguje stejně.
>>> mc.b
2
>>> MyClass.b
2
>>> mc.b = 'svete'
>>> mc.b
'svete'
>>> MyClass.b
'svete'
📝
Provedením mc = MyClass jsme pouze objektu v paměti „přilepili“ další identifikátor.

Tímto způsobem jsme vlastně zavedli alias na základní třídu, což nám bude v budoucnu k užitku.

3

Instance třídy I

Operování přímo s konkrétními třídami jako na předchozím slajdu je sice možné, ale dost by omezovalo jejich použití. Zajímavější je, pokud uvedenou třídu použijeme jako konstruktor pro jednotlivé její instance: 

>>> class MyClass:
...     a, b, c = 1, 2, 3
... 
>>> MyClass
<class '__main__.MyClass'>
>>> dir(MyClass)
['__class__', '__delattr__', '__dict__', '__doc__', '__eq__', '__format__',
 '__ge__', '__getattribute__', '__gt__', '__hash__', '__init__', '__le__',
 '__lt__', '__module__', '__ne__', '__new__', '__reduce__', '__reduce_ex__',
 '__repr__', '__setattr__', '__sizeof__', '__str__', '__subclasshook__',
 '__weakref__', 'a', 'b', 'c']

# A) Instance 'mc1' třídy 'MyClass' podědí vlastnosti svého rodiče:
>>> mc1 = MyClass()
>>> mc1
<__main__.MyClass object at 0xb75dda0c>
>>> MyClass.a
1
>>> mc1.a
1

# B) Pokud na potomkovi ale něco změníme, rodič se to nedozví:
>>> mc1.a = 'ahoj'
>>> mc1.a
'ahoj'
>>> MyClass.a
1

# C) Podobně pokud nyní změníme něco na rodiči,
#    potomek bude taktéž zanechán v blahé nevědomosti:
>>> MyClass.a = 'svete'
>>> MyClass.a
'svete'
>>> mc1.a
'ahoj'

# D) Nový potomek 'mc2' ale nyní podědí i nový stav rodiče:
>>> mc2 = MyClass()
>>> mc2
<__main__.MyClass object at 0xb75ddd6c>
>>> mc2.a
'svete'

Všimněte si, že při použití třídy jako konstruktoru ji voláme, tedy se závorkami – MyClass().

4

Instance třídy II

Situace se „kapku“ změní, pokud atribut je proměnného typu a použijeme operace pro úpravu hodnot tohoto typu: 

>>> class MyClass:
...     a, b = 1, [2, 3]

# A) Instance třídy podědí vlastnosti svého rodiče:
>>> mc1 = MyClass()
>>> mc1.a
1
>>> mc1.b
[2, 3]

# B) A pokud na potomkovi přesměrujeme odkaz na jiný typ, rodič se to nedozví:
>>> mc1.b = 'ahoj'
>>> mc1.b
'ahoj'
>>> MyClass.b
[2, 3]

# C1) Když se ale místo změny hodnoty začneme přehrabovat ve vnitřnostech
#     proměnného datového typu, začnou se dít věci:
>>> mc2 = MyClass()
>>> mc2.b
[2, 3]
>>> mc3 = MyClass()
>>> mc3.b
[2, 3]
>>> mc2.b.append(4)
>>> mc2.b
[2, 3, 4]
>>> mc3.b
[2, 3, 4]
>>> MyClass.b
[2, 3, 4]

# C2) A to samozřejmě nezávisle na místě způsobení změny:
>>> mc3.b.append(5)
>>> mc3.b
[2, 3, 4, 5]
>>> mc2.b
[2, 3, 4, 5]
>>> MyClass.b
[2, 3, 4, 5]

# C3) Nepřekvapivě na potomka, který zaměnil typ za jiný, to ale nemá vliv:
>>> mc1.b
'ahoj'
5

Funkce jako atributy tříd I

Kromě „obyčejných“ proměnných můžeme do tříd schovat samozřejmě i funkce. A dokud se ke třídě chováme jako ke jmennému prostoru, všechno funguje přesně tak, jak bychom čekali: 

        >>> class T:
        ...     
        ...     a = 'Ahoj!'
        ...     
        ...     def fn(x):
        ...         return f'Zavoláno: fn({x})'

        >>> T.a
        'Ahoj!'
        >>> T.fn
        <function T.fn at 0x000001F4751C0D60>
        >>> T.fn(666)
        'Zavoláno: fn(666)'
        >>> T.fn('Baf!')
        'Zavoláno: fn(Baf!)'
6

Funkce jako atributy tříd II

Jakmile ale začneme třídy používat jako konstruktory instancí, vystrčí na nás nos podle mě kardinálně špatné rozhodnutí tvůrců Python'u: 

        >>> class T:
        ...     
        ...     a = 'Ahoj!'
        ...     
        ...     def fn(x):
        ...         return f'Zavoláno: fn({x})'

        >>> t = T()
        >>> t.fn
        <bound method T.fn of <__main__.T object at 0x000001F4749AB830>>
        >>> t.fn(666)
        Traceback (most recent call last):
          File "<pyshell#7>", line 1, in <module>
            t.fn(666)
        TypeError: T.fn() takes 1 positional argument but 2 were given

Dva poziční argumenty? Jenom proto, že jsem funkci zavolal na instanci? Co to má znamenat?

7

Funkce jako atributy tříd III

Dobře, zkusme se tomu přizpůsobit: 

        >>> class T:
        ...     
        ...     a = 'Ahoj!'
        ...     
        ...     def fn(x, y):
        ...         return f'Zavoláno: fn({x}, {y})'

        >>> t = T()
        >>> t.fn(666)
        'Zavoláno: fn(<__main__.T object at 0x000001F47518C920>, 666)'

        >>> t
        <__main__.T object at 0x000001F47518C920>

Aha, takže funkce na instanci (neboli tedy metoda instance) dostane jako první parametr referenci na tuto instanci. Nezvyklé, ale dává to smysl asi tak stejně dobře, jako automagické objevování se této reference v podobě klíčového slova this v jiných jazycích.

8

Funkce jako atributy tříd IV

Jenže to má ten důsledek, že jedna a ta samá funkce se v rámci instance volá s jiným počtem parametrů než v rámci jmenného prostoru třídy: 

        >>> class T:
        ...     
        ...     a = 'Ahoj!'
        ...     
        ...     def fn(x, y):
        ...         return f'Zavoláno: fn({x}, {y})'

        >>> T.fn(666)
        Traceback (most recent call last):
          File "<pyshell#13>", line 1, in <module>
            T.fn(666)
        TypeError: T.fn() missing 1 required positional argument: 'y'
        >>> T.fn('Baf!', 666)
        'Zavoláno: fn(Baf!, 666)'
9

Instanční metody – jak to mělo být

Kdyby bývaly byly tyto funkce, co se chovají jinak v rámci třídy a jinak v rámci instance, nějak označeny, například takovýmto dekorátorem.. 

        class T:
            
            a = 'Ahoj!'
            
            @instancemethod
            def fn(x, y):
                return f'Zavoláno: fn({x}, {y})'

..neřekl bych ani slovo – znalí dekorátorů by věděli, že daná funkce se nejspíš bude chovat úplně jinak, než je napsána, neznalí by díky tomu označení zase alespoň tušili, že to nebude jen tak nějaká obyčejná funkce.

Nejhorší na tom je, že to tak mohlo být (ostatně vizte dále třídní metody)! Ale tvůrci jazyka se rozhodli, že když už někdo používá třídy, chce je především kvůli instančním metodám, tak mu přece ušetříme psaní a nebudeme je nijak označovat. Výsledek je chmurný – def v bloku class se chová podle toho, kde a jak ji použijete :-(

10

Instanční metody – jak to bohužel je

Nakonec tedy bohužel, funkce bez dekorátoru v bloku třídy jsou automaticky brány jako instanční a při svém volání na instanci automaticky dostanou navíc referenci na tuto instanci jako svůj první poziční parametr (což je přesně práce dekorátoru, kdyby tam býval byl!): 

        class T:
            
            a = 'Ahoj!'
            
            def fn(self, y):
                return f'Zavoláno: fn({self}, {y})'

Nemusí se nám to líbit (mně ani trochu), ale prostě to tak je :-(

PS: Název self se pro tento první atribut používá čistě dohodou, aby se zdůraznilo, že jde o referenci na instanci. Ve vlastním zájmu tuto dohodu neporušujte – je to jediná nápověda, že se tyto funkce chovají jinak, než by člověk z jejich zápisu čekal.

11

Třídní metody I

Důvod, proč jsem ze stavu instančních metod tak nakvašený, je v tom, že existují i třídní metody – které očekávaně operují nad atributy třídy, nikoli instance – a ty se samozřejmě pomocí dedikovaného dekorátoru zavádí: 

        >>> class T:
        ...     
        ...     a = 'Ahoj!'
        ...     
        ...     @classmethod
        ...     def fn(x, y):
        ...         return f'Zavoláno: fn({x}, {y})'

        >>> t = T()
        >>> t.fn(666)
        "Zavoláno: fn(<class '__main__.T'>, 666)"
        >>> T
        <class '__main__.T'>

Třídní metody tedy při svém volání také automaticky dostávají navíc (první) poziční parametr, ale je jím reference na příslušnou třídu. A nikoho toto chování nepřekvapí, protože před funkcí je v definici napsaný dekorátor, který na to upozorňuje.

12

Třídní metody II

Z pochopitelných důvodů se tento atribut prozměnu dohodou označuje jako cls.. 

        class T:
            
            a = 'Ahoj!'
            
            @classmethod
            def fn(cls, y):
                return f'Zavoláno: fn({cls}, {y})'

..a každý vidí, že má smysl se tím řídit – hned na první pohled je jasné, že jde o reterenci na třídu (class).

13

Statické metody

Abychom kyselý koláč dojedli rovnou celý, tak existuje ještě jeden dekorátor pro metody tříd: 

        class T:
            
            a = 'Ahoj!'
            
            @staticmethod
            def fn(x, y):
                return f'Zavoláno: fn({x}, {y})'

Ano, hádáte správně – takto označené funkce se chovají při volání ve jmenném prostoru třídy a na instanci stejně, tj. očekávají přesně stejný počet parametrů, s jakým jsou zapsány (zde tedy dva). Člověk se nemůže zbavit pocitu, proč se funkce, která se chová přesně tak, jak byste čekali, musí označovat nějakým dekorátorem…

14

Emulace typu „record“ z jazyka Pascal

Nehledě na (podle mě) nevhodný a matoucí zápis, když už jsme se s tímto rozdílem mezi atributy instančními a třídními seznámili, můžeme tu vlastnost, že atributy instance nemají s atributy třídy nic společného, využít ještě o kus dál – na každé instanci si můžeme dodefinovat libovolné další atributy, které potřebujeme.

Prakticky úplnou obdobu pascalovského typu záznam (record) tak získáme například takto: 

class Zaměstnanec:
    pass

jan = Zaměstnanec()   # vyrobení prázdného záznamu o zaměstnanci

# naplnění polí (atributů) záznamu
jan.jméno = 'Jan Novák'
jan.oddělení = 'počítačová laboratoř'
jan.plat = 15000
📝
Upraveno podle dokumentace.

Prostě jsme vytvořili prázdný objekt, z něj vyrobili taktéž zcela prázdnou instanci a do ní jsme „naházeli“ všechna potřebná data.

15

Metody I

Většinou (alespoň v programování obecně) se tedy třídy používají tak, že spolu s daty zapouzdřují i funkce, které umí s příslušnými daty správně pracovat. Těmto funkcím, které operují na datech dané instance (případně i třídy), se říká metody.

Vyrobme si ukázkovou třídu Člověk s jednou metodou identifikace():

📄 Program: alisa.py
▶ Output
📝
Zatímco v rámci třídy je identifikace „obyčejnou“ funkcí, v rámci instance se již jedná o metodu dané instance (bound method).

Až na parametr self voláme tuto metodu standardně – předáváme pouze další dodatečné parametry (což v tomto případě znamená parametr žádný).

16

Metody – „self“

Jak už víme, pokusíme-li se metodu identifikace() zavolat přímo na třídě, se zlou se potážeme.. 

Člověk.identifikace()
  -->
TypeError: identifikace() takes exactly 1 argument (0 given)

..zatímco volání na instanci nečiní žádné potíže: 

alisa.identifikace()
  -->
"Dobrý den! Jmenuji se Алиса Селезнева."

Celý „vtip“ je schován v tom, že parametr self metody identifikace() odkazuje na právě zavedenou instanci třídy, která je při volání příslušné metody předána Python'em automaticky jako její první parametr, tj.:

Při zavolání této metody ve výše uvedeném tvaru alisa.identifikace() se tak vlastně ve skutečnosti volá kód Člověk.identifikace(alisa).
📝
Tady je důvod pro pojmenování self asi vidět nejjasněji.
17

Poznámka: Alias na atribut

PS: V Python'u můžete atributy třídy/instance vesele aliasovat a volat pod těmito novými jmény, např.: 

# Po zavedení..
fn = alisa.identifikace
# ..pak můžeme volat:
fn()  -->  "Dobrý den! Jmenuji se Алиса Селезнева."

V principu jde o úplně stejnou techniku jako u aliasů tříd – prostě jen konkrétnímu objektu (zde metodě) přiřadíme další jméno („nálepku“), pod kterým se na něj nadále můžeme odkazovat.

18

Inicializace atributů

Většinou nebudeme chtít vyrobit instanci třídy (pouze) s hodnotami, jaké jí poskytla rodičovská třída. V takovém případě doplníme třídu o metodu __init__(). Ta zaručuje, že každá nově vytvořená instance bude obsahovat též takové hodnoty, které pošleme jako parametr do třídního konstruktoru: 

# Při zavedení třídy..
class Člověk():
    """Objektová reprezentace člověka."""

    def __init__(self, jméno, datum_narození, krevní_skupina):
        self.jméno = jméno
        self.datum_narození = datum_narození
        self.krevní_skupina = krevní_skupina

# ..pro konkrétní instanci..
alisa = Člověk(
    'Алиса Селезнева',
    '2065-11-17',
    '0',
  )

# ..dostaneme:
alisa.jméno --> Алиса Селезнева
alisa.krevní_skupina --> 0
📝
Výrazy typu self.jméno = jméno nedělají nic magického – prostě na dané instanci (self) zavedou nový atribut (zde jméno), kterému přiřadí příslušnou výchozí hodnotu. Že se daný atribut jmenuje stejně jako příslušný parametr konstruktoru (tedy funkce __init__()), je pouze úzus. Klidně by se mohl jmenovat úplně jinak, ale z důvodů čitelnosti se to nedělá – na první pohled je takto jasné, kde příslušný parametr z inicializace instance skončí.

Všimněte si (a zapamatujte), že __init__() je zase pouze „obyčejná“ instanční metoda a jako taková dostává automaticky implicitní první parametr v podobě odkazu na právě zaváděnou instanci třídy. Při inicializaci se tedy vlastně volá kód Člověk.__init__(alisa, 'Алиса Селезнева', '2065-11-17', '0').

📝
PS: Až na to, že narozdíl od jiných metod instance v případě initu to takto přímo zavolat nejde – objekt alisa by totiž už musel existovat (což se sice dá zařídit a také se tak děje, ale je to výrazně složitější a mimo rámec této přednášky).

PS: Na parametry konstruktoru se nepřekvapivě vztahují podobná pravidla jako na parametry funkcí. Můžete tedy používat pojmenované parametry s výchozí hodnotou apod.

19

Dědičnost I

Dědičnost v rámci Python'u vyjádříme jako parametr při zavádění třídy. Školáka jako upraveného Člověka tak vyrobíme třeba takto: 

  class Školák(Člověk):
    """Objektová reprezentace školáka."""
    
    def __init__(self, jméno, datum_narození, krevní_skupina, třída, předměty):
        Člověk.__init__(self, jméno, datum_narození, krevní_skupina)
        self.třída = třída
        self.předměty = předměty

A podobně i pro Učitele: 

  class Učitel(Člověk):
    """Objektová reprezentace učitele."""
    
    def __init__(self, jméno, datum_narození, krevní_skupina, třída, předměty, výplata):
        Člověk.__init__(self, jméno, datum_narození, krevní_skupina)
        self.třída = třída
        self.předměty = předměty
        self.výplata = výplata

__init__() nadřazené třídy s příslušnými parametry tedy musíme v potomkovi zavolat sami, nikdo jiný to za nás neudělá!

📝
Přesněji řečeno – nadřazený __init__() musíte explicitně zavolat, měníte-li způsob inicializace dané instance (tedy například počet parametrů či jejich význam). Pokud ho na potomkovi vůbec nezavedete, volá se na příslušném rodičovi automaticky sám.
📝
Při dědění z jednoho rodiče je velmi vhodné explicitní volání jménem rodičovské třídy nahradit voláním funkce super() bez parametrů: super().__init__(jméno, datum_narození, krevní_skupina). To je totiž v tomto jednoduchém případě ekvivalentní volání super(Školák, self).__init__(jméno, datum_narození, krevní_skupina) .
📝
Python podporuje i vícenásobnou dědičnost, „rodičů“ tudíž může být víc jak jeden. Při vyhledávání atributů jsou pak zjednodušeně řečeno prohledávány třídy v zadaném pořadí a do šířky.
20

Příklad

Budeme-li pokračovat v příkladu, bude upravené zavedení objektu typu Školák vypadat takto: 

  alisa = Školák(
        'Алиса Селезнева',
        '2065-11-17',
        '0',
        '3. A',
        {'matematika': 1, 'zeměpis': 1, }
      )

  alisa.jméno --> Алиса Селезнева
  alisa.třída --> 3. A

Zde se tedy prozměnu (jakoby) volá: Školák.__init__(alisa, 'Алиса Селезнева', '2065-11-17', '0', '3. A', {'matematika': 1, 'zeměpis': 1, }).

21

Dědičnost II

I když použijeme super(), pořád se na rodičovskou třídu odkazujeme jejím jménem při zavedení poděděné třídy a při případné refaktorizaci kódu nás tak čeká spousta práce s přepisováním (a nezapomenutím na nějaký výskyt).

Tento problém je ovšem možné snadno vyřešit – stačí zavést alias na rodičovskou třídu a v kódu používat dále pouze ten (což jsme ostatně viděli už na druhém slajdu): 

  class Člověk():
    ...
  
  AliasČlověk = Člověk
  
  class Školák(AliasČlověk):
    ...
📝
Samozřejmě nezáleží na tom, jak svůj alias pojmenujete, je to normální „proměnná“.

Při refaktorizaci pak stačí zaměnit jediné místo kódu.

Mimochodem něco podobného se týká i rodičovských tříd definovaných v jiných modulech. Chcete-li z takové třídy dědit, musíte ji nejdříve do aktuálního modulu naimportovat. A jestli ji naimportujete jako součást celého modulu, nebo pouze ji, nebo pod nějakým jiným jménem, je zcela na vás.

22

Dědičnost III

Neupravuje-li potomek chování rodičovské inicializace, metodu __init__() pak na něm dokonce ani nemusíme definovat a Python zavolá příslušnou rodičovskou sám. Pokud však jakoukoli rodičovskou instanční metodu (tedy i __init__()) na potomkovi předefinujeme, příslušný rodičovský originál musíme – vyžaduje-li to logika kódu – zavolat sami: 

class Rodič:
    ...
    def fn(self, atr1):
        ...
    ...

class Potomek(Rodič):
    ...
    # upravená metoda 'fn()'
    def fn(self, atr1, atr2):
        # případné volání rodičovské metody
        Rodič.fn(self, atr1)
        # následuje kód, kde (snad :) využijeme i 'atr2'
        ...
    ...

PS: Tohle je přesně místo, kde budete chtít použít super(). Jelikož tato funkce toho ale umí mnohem víc, než by člověk na první pohled čekal, je jí věnována samostatná přednáška.

23

Metody II

Potomek podědí z rodiče jeho atributy i metody. Obé z toho může přepsat vlastní definicí (nebo pouze nějak doplnit). Ale stejně tak si samozřejmě může zavést atributy a metody zcela vlastní.

Doplňme naši ukázkovou třídu Školák o metodu pro výpočet průměrné známky ze všech předmětů (ostatní kód zůstává stejný): 

  class Školák(Člověk):
    ...
    def průměrná_známka(self):
        """Vrací průměr všech známek studenta."""
        součet = 0
        for předmět in self.předměty:
            součet += self.předměty[předmět]
        return součet / len(self.předměty)

Nyní budou instance třídy Školák obsahovat oproti instancím třídy Člověk navíc i metodu průměrná_známka().

PS: Jak už víme z dřívějška, pro volání metody platí následující ekvivalence: 

  # Volání..
  alisa.průměrná_známka() --> 1
  # ..je ekvivalentní volání:
  Školák.průměrná_známka(alisa)
24

Třídní atributy

Někdy se nám ale může hodit operovat nikoli s atributy konkrétní instance třídy, nýbrž s atributy rodiče. Vzpomeneme-li si na první slajd, je implementace jasná – stačí vynechat slovíčko self a odkazovat se přímo na uvedenou rodičovskou třídu (neuvedený kód se opět zachovává): 

  class Školák(Člověk):
    ...
    školáků = 0
    ...
    def __init__(self, ...):
        ...
        Školák.školáků += 1

Síla třídních atributů tkví v tom, že jsou sdíleny všemi instancemi třídy mezi sebou navzájem (jak už jsme viděli), takže jakákoli změna v nich je viditelná ve všech jednotlivých instancích/objektech vytvořených z dané třídy.

PS: Zjevně místo Školáka můžete dosadit libovolný jiný dostupný objekt, ale to už by daný kód dělal něco úplně jiného, než jste zamýšleli… Proto je mnohem lepší napsat to rovnou jako dále pomocí třídní metody.

25

Třídní metody

Na třídních atributech operují komplementární třídní metody (označené dekorátorem @classmethod).. 

  class Školák(Člověk):
    ...
    školáků = 0
    ...
    
    def __init__(self, ...):
        ...
        self.přidej_školáka()
  
    @classmethod
    def přidej_školáka(cls):
        cls.školáků += 1

..které prozměnu jako první implicitní parametr dostávají referenci na celou příslušnou třídu. Zavedení nové instance v tomto případě tedy způsobí následující řetěz volání: 

    alisa = Školák(…)
    ⇒ Školák.__init__(alisa, …)
    ⇒ alisa.přidej_školáka()
    ⇒ přidej_školáka(Školák)
    ⇒ Školák.školáků += 1
26

PS: Poznámka k dekorátorům metod

Jak už jsem říkal, podle mého by bývalo bylo mnohem lepší, kdyby se dekorátory metod zavedly opačným způsobem: 

        class Třída:
        
            def statická_metoda(...):
                ...
        
            @classmethod
            def třídní_metoda(cls, ...):
                ...
        
            @instancemethod
            def instanční_metoda(self, ...):
                ...

Neoznačené metody by se volaly jako normální funkce se správným počtem parametrů a u dekorovaných by každému na první pohled bylo jasné, že je něco jinak, a dal by si pozor, co píše. Bohužel zvítězil názor, že: „Třídy chtějí lidé především kvůli instancím, tak instanční metody zavedeme bez dekorátoru, ať ušetříme psaní.“ Psaní jsme sice ušetřili, ale jako bonus jsme získali solidní guláš…

27

„Privátní“ atributy

Python nemá koncepci skutečně soukromých, privátních atributů. Ale jakýkoliv atribut, jehož jméno začíná alespoň dvěma podtržítky a končí podtržítkem nejvýše jedním se bude jako privátní tvářit – nebude totiž na třídě (ani instanci) pod tímto jménem dostupný: 

>>> class MyClass:
...     a = 1
...     __b = 2

# Na atribut 'a' se dostaneme normálně:
>>> MyClass.a
1

# S atributem '__b' už to nejde:
>>> MyClass.__b
Traceback (most recent call last):
  File "<pyshell#12>", line 1, in <module>
    MyClass.__b
AttributeError: type object 'MyClass' has no attribute '__b'
📝
Technicky dojde k nahrazení jména atributu __atribut za _classname__atribut, kde classname je vytvořeno ze jména příslušné třídy (z něhož jsou nejdříve odstraněna případná začáteční podtržítka). V tomto příkladě bude tedy třída obsahovat atribut MyClass._MyClass__b (který se takto i bude vypisovat v rámci dir(MyClass)).

Podobně atributy (data i metody) začínající na jedno podtržítko jsou konvencí brány za neveřejnou část API (rozhraní třídy). Narozdíl od dvojpodtržítkových jsou vidět a jsou normálně přístupné, ale všichni by se jim měli vyhýbat jako čert kříži ^_~

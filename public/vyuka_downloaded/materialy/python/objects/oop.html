OOP v Python'u

by Jiří Znamenáček

1

Úvod

Rozhodně bych nechtěl tvrdit, že v Python'u se nedá programovat OOP-způsobem. Ostatně už pohled do standardní knihovny by mě usvědčil ze lži. A armáda introspekčních nástrojů také. Co ale tvrdit chci:

Python není primárně OOP-jazyk. A stejně jako u mnoha jiných oblastí v Python'u i programování podle principů OOP se řídí spíš konvencí než vynucovacími prostředky jazyka.
📝
Příklad pro uvedení do problematiky: V Python'u neexistuje koncept privátních atributů. Můžete sice některé atributy označit za „privátní“, ale to ostatním nezabrání se v nich hrabat, pokud budou chtít. Prostě se předpokládá, že když je takto označíte, budou je tak brát i ostatní.

3

Instance třídy

Instanci třídy Školák pod jménem alisa zavedeme tímto způsobem: 

alisa = Školák(
      'Алиса Селезнева',
      '2065-11-17',
      '0',
      '3. A',
      {'matematika': 1, 'zeměpis': 1, }
    )

Porovnáme-li volání konstruktoru s jeho zdrojovým kódem z předchozího slajdu (ponechal jsem pouze relevantní části kódu).. 

class Školák(Člověk):
 
    def __init__(self, jméno, datum_narození, krevní_skupina, třída, předměty):
      Člověk.__init__(self, jméno, datum_narození, krevní_skupina)
      self.třída = třída
      self.předměty = předměty

..vidíme, že konstruktoru posíláme o jeden parametr méně, než očekává. Onen „podivný“ první parametr self je automaticky předáván všem instančním metodám a je jím odkaz na právě zpracovávanou instanci (jak si ukážeme na dalším slajdu).

📝
Asi ve většině OOP-jazyků se tento atribut jmenuje převážně this a je „automagicky“ přítomen v těle příslušných metod. Zda je přehlednější jeho implicitní přítomnost nebo explicitní předání jako prvního vstupního argumentu, ponechávám na vkusu každého uživatele.
4

Argument „self“

Funkci explicitního argumentu self (který nahrazuje rozšířenější implicitní argument this z většiny OOP-jazyků) snadno osvětlí následující příklad nad již zavedenými objekty: 

>> Školák
<class '__main__.Školák'>
>> Školák.__init__
<function __init__ at 0x154f408>

>> alisa
<__main__.Školák object at 0x154c5d0>
>> alisa.__init__
<bound method Školák.__init__ of <Školák object at 0x154c5d0>>

Nepřekvapivě tedy parametr self obdrží při volání příslušné metody právě onu instanci, na niž je daná metoda právě vázána (bound). Zde pro případ konstruktoru tedy volání.. 

    alisa = Školák( 'Алиса Селезнева', '2065-11-17', '0',
                    '3. A', {'matematika': 1, 'zeměpis': 1, } )

..způsobí zavolání kódu: 

    Školák.__init__( alisa, 'Алиса Селезнева', '2065-11-17', '0',
                            '3. A', {'matematika': 1, 'zeměpis': 1, } )
📝
Tedy, tohle platí pro jakoukoliv jinou instační metodu, když už je objekt alisa k dispozici. Zrovna pro __init__() je třeba ho nejdříve (kapku neprůhledně) vyrobit: 
        alisa = Školák.__new__(Školák)
5

Konstruktor „__init__()“ I

Podívejme se nyní pořádně na vlastní metodu konstruktoru __init__(): 

class Školák(Člověk):
 
    def __init__(self, jméno, datum_narození, krevní_skupina, třída, předměty):
      Člověk.__init__(self, jméno, datum_narození, krevní_skupina)
      self.třída = třída
      self.předměty = předměty

Vidíme, že poděděná třída (zde Školák) se musí sama postarat o zavolání konstruktoru nadřazené třídy (zde Člověk) se správnými parametry. Toto volání je v tomto případě v principu možno provést dvěma způsoby:

  • Přímým odkazem na rodičovskou třídu: 
                Člověk.__init__(self, jméno, datum_narození, krevní_skupina)
    📝
    To je sice zcela průhledné, leč je to další místo, které můžeme zapomenout upravit, rozhodneme-li se později provést přejmenování rodičovské třídy nebo komplexnější refaktorizaci.
  • Odkazem na příslušnou rodičovskou třídu pomocí vestavěné funkce super(), a to bez parametrů: 
                super().__init__(jméno, datum_narození, krevní_skupina)
    📝
    Toto je asi nejlepší možné řešení a pro případ jednoduché dědičnosti (tedy když má třída pouze jednoho rodiče) i nejpřehlednější.

Poznámka – „datové“ třídy I

Jistě jste si (a nejenom u Python'u) všimli, že volání metody __init__() v případech pouhého nastavení (instančních) atributů na nějakou vstupní hodnotu je ukázkový příklad ukecanosti a opakování kódu. Python 3.7 tak přinesl několik zkratek, jak se uvedenému opakování vyhnout.

Pokud potřebujete rychle nastavit data nějaké třídě: 

        from dataclasses import make_dataclass
        
        Point = make_dataclass('Point', ['x', 'y', 'z'])
        
        p = Point(1.5, 2.5, 3.0)
        print(p)    # Point(x=1.5, y=2.5, z=3.0)
📝
PS: Součástí definice mohou být i anotace a složitější konstrukce, například: 
            make_dataclass('C',
                [('x', int), 'y', ('z', int, field(default=5))],
                namespace={'add_one': lambda self: self.x + 1}
            )
Pak už je to ale spíš jen asi-ne-tak-úplně-přehledná zkratka za následující plnou formu.

Pokud potřebujete s nastavovanými atributy dále i něco dělat: 

        from dataclasses import dataclass
        from typing import Any
        
        @dataclass
        class C:
            x: int
            y: Any
            z: int = 5

            def add_one(self):
                return self.x + 1

        c = C(1, 'ahoj')
        print(c)    # C(x=1, y='ahoj', z=5)
8

Poznámka – „datové“ třídy II

Popravdě možností jsou mraky:

  • Ve výchozím nastavení nagenerují oba způsoby kromě __init__() i __repr__() a __eq__(). Všechno můžete selektivně vypnout, ale stejně tak dobře (pomocí parametru dekorátoru order=True) můžete nechat přigenerovat i zbylé řadicí operátory __lt__(), __le__(), __gt__(), __ge__().
  • Potřebujete-li něco provést po nastavení atributů, stačí připsat metodu __post__init__().
  • Vyžadují-li atributy něco speciálního, je k dispozici funkce field().
    📝
    Typické je např. použití při nahrazování výchozích hodnot proměného typu. Zatímco.. 
                        class X:
                        x = []
    ..způsobí, že všechny instance uvidí v atributu x stejný seznam, následující kód už přiřadí každé instanci vlastní: 
                        @dataclass
                    class X:
                        x: list = field(default_factory=list)
    PS: S anotacemi ten první kód ani nespustíte, takže vás to trkne.
  • Jelikož dataclasses jsou často opravdu jen balíky hodnot, může se vám hodit převést je na slovník (funkce modulu asdict()) nebo n-tici (astouple()).
  • …

Pro podrobnosti navštivte originální dokumentaci.

Vícenásobná dědičnost

Python umožňuje vyrobit třídu s více než jedním rodičem: 

      class Třída(Rodič1, Rodič2, ...):
...

Aby se vyhnul „oblíbenému“ problému diamantu, používá upravený perlovský algoritmus pro vyhledání zdroje vykonání příslušné zavolané metody (či vlastnosti). Ten se dá stručně shrnout tak, že dědičnost se řídí pořadím rodičovských tříd, a to postupně prohledáváním do hloubky. Koho zajímají podrobnosti, bude se chtít podívat na MRO (Method Resolution Order).

12

Instanční atributy

Jakákoliv „obyčejná“ (tedy nijak „neoznačená“, viz následující slajdy) funkce na třídě se z hlediska volání chová jako instanční metoda. (V našem příkladě je takovou metodou funkce průměrná_známka na třídě Školák.)

📝
Instanční atributy jsou tedy vázány (bound) na konkrétní instance tříd.

Ukázka použití: 

  class Školák(Člověk):
    
    def __init__(self, ...):
...
        self.předměty = předměty
    
    def průměrná_známka(self):
      součet = 0
      for předmět in self.předměty:
          součet += self.předměty[předmět]
      return součet / len(self.předměty)

Jak už jsme viděli v případě funkce __init__(), instanční metody automaticky dostávají první parametr, kterým je právě daná konkrétní instance třídy. Konkrétní volání se pak překládá podle následujícího schématu: 

    # zavolání..
    alisa.průměrná_známka()
    # ..je ekvivalentní zavolání
    Školák.průměrná_známka(alisa)

To je ostatně důvod, proč se tomuto parametru vřele doporučuje říkat právě self, i když to není povinné.

13

Třídní atributy

Někdy se nám ale může hodit operovat nikoli s atributy konkrétní instance třídy, nýbrž s atributy rodiče, tedy celé třídy. (V naší testovací struktuře je takovým atributem atribut školáků ve třídě Školák.)

📝
Síla třídních atributů tkví v tom, že jsou sdíleny všemi instancemi třídy mezi sebou navzájem, takže jakákoli změna v nich je viditelná ve všech jednotlivých instancích/objektech vytvořených z dané třídy.

Na třídních atributech operují komplementární třídní metody (@classmethod), jejichž použití je následující: 

  class Školák(Člověk):
...
    školáků = 0
...
    
    def __init__(self, ...):
...
        self.přidej_školáka()
    
    @classmethod
    def přidej_školáka(cls):
        cls.školáků += 1
📝
@classmethod je tzv. dekorátor funkce. Prozatím ho berte jako část syntaxe jazyka, která slouží k označení třídnosti dané metody.

Podobně jako metody instanční, třídní metody také automaticky dostávají první parametr. Narozdíl od instačních metod ale tímto parametrem není příslušná instance, nýbrž původní třída! Konkrétní volání tedy vlastně vypadá takto: 

    # zavolání..
    alisa.přidej_školáka()
    # ..je ekvivalentní zavolání
    alisa.přidej_školáka(Školák)

Z úplně stejného důvodu jako u instančních metod se pro lepší čitelnost doporučuje tento parametr značit jako cls (což opět není povinné, ale asi už chápete, proč je to velmi doporučované).

14

Statické atributy

Kromě instančních a třídních metod v Python'u existují i metody statické, zaváděné pomocí dekorátoru @staticmethod: 

    @staticmethod
    def pomocná_metoda(par1, par2):
...

Jak je vidět, narozdíl od běžných (instančních) metod a metod třídních neočekávají – a také nedostávají – žádný první implicitní parametr.

📝
Můžete být v pokušení zavádět na třídách metody bez implicitního vstupního parametru a přitom je neoznačovat jako statické. Tyto funkce budou volatelné (přes tečkovou notaci) na příslušné třídě, ale už ne na její instanci – ta totiž při každém volání na začátek přidá samu sebe automaticky.
15

„Privátní“ atributy

Python nemá koncepci skutečně soukromých, privátních atributů. Ale jakýkoliv atribut, jehož jméno začíná alespoň dvěma podtržítky a končí podtržítkem nejvýše jedním se bude jako privátní tvářit – nebude totiž na třídě (ani instanci) pod tímto jménem zvenku* dostupný: 

>>> class MyClass:
...     a = 1
...     __b = 2

# Na atribut 'a' se dostaneme normálně:
>>> MyClass.a
1

# S atributem '__b' už to nejde:
>>> MyClass.__b
Traceback (most recent call last):
  File "<pyshell#12>", line 1, in <module>
MyClass.__b
AttributeError: type object 'MyClass' has no attribute '__b'
📝
* Uvnitř třídy se na něj ale samozřejmě tímto dvojpodtržítkovým jménem normálně odkazuje.
📝
PS: Technicky dojde k nahrazení jména atributu __atribut za _classname__atribut, kde classname je vytvořeno ze jména příslušné třídy (z něhož jsou nejdříve odstraněna případná začáteční podtržítka). V tomto příkladě bude tedy třída obsahovat atribut MyClass._MyClass__b (který se takto i bude vypisovat v rámci dir(MyClass)).

Podobně atributy (data i metody) začínající na jedno podtržítko jsou konvencí brány za neveřejnou část API (rozhraní třídy). Narozdíl od dvojpodtržítkových jsou vidět a jsou normálně přístupné, ale všichni by se jim měli vyhýbat jako čert kříži ^_~

Deskriptory (aka „properties“)

Za implementací všech předchozích typů volání stojí tzv. protokol deskriptorů, po staru známý spíše pod anglickým jménem properties nebo pod jejich ekvivalentním označením ve spoustě jiných programovacích jazyků getters & setters. Ukažme si rovnou příklad: 

    class Plocha:
        
        def __init__(self, barva=None):
            self.__barva = barva
     
        @property
        def barva(self):
            return self.__barva
         
        @barva.setter
        def barva(self, val):
            self.__barva = val
         
        @barva.deleter
        def barva(self):
            del self.__barva
📝
Dekorátor @property učiní příslušný atribut (zde barva) přístupný pro získání hodnoty (tedy pro odpověď na dotaz INSTANCE.barva), dekorátor @ATRIBUT.setter pro přepis hodnoty (tedy reakci na výraz INSTANCE.barva = HODNOTA) a dekorátor @ATRIBUT.deleter pro zrušení atributu (tedy reakci na příkaz del INSTANCE.barva).
📝
Pro tento konkrétní příklad pominu, že zavést atribut s příslušným chováním je asi lepší (a rozhodně čitelnější) radši pomocí k tomu určené (byť starší) funkce property().

K objektu s takto zavedenými metodami se pak můžeme chovat následujícím způsobem: 

# zavedení instance Plochy červené barvy
>>> plocha = Plocha('červená')
>>> plocha.barva
'červená'

# změna barvy plochy na zelenou
>>> plocha.barva = 'zelená'
>>> plocha.barva
'zelená'
📝

Užití OOP

Kdy tedy OOP použít? Z hlediska samotného Python'u především v těchto případech:

  • Když potřebujete zapouzdřit nějaké hodnoty (a občas i funkce) do vlastního jmenného prostoru.
    📝
    Python samotný totiž jinak dokáže vytvořit vlastní kontext už jen pouze pro celý modul a těla funkcí (čili i metod), jinde ne.
  • Když chcete vyrobit objekty, které umí využívat nějaké vestavěné funkce nebo operátory.
    📝
    Přímo přetížit vestavěný typ nemůžete, ale odvodit si vlastní ano – magických metod je v zásobě hromada. Nu a konečně je to skvělá příležitost pro využití operátoru @, který jinak nic v Python'u nepoužívá ^_~

Druhá část odpovědi se týká použití tříd v běžné programátorské praxi – tam se vám budou asi nejvíc hodit:

  • Když potřebujete dědičnost – typicky kvůli polymorfismu nebo třeba váš tým při práci používá tzv. dyzajnové vzory (design patterns).
  • Při implementaci stavových automatů – třída stav drží a zároveň s ním umí i operovat.
  • …
📝
Pro zajímavost: Kolegové z firmy, kde je Python s přehledem prvním programovacím jazykem, zjišťovali, kdo ve svých kódech používá třídy, a našli celého jednoho člověka. Z hlediska Python'u myslím typický výsledek – většinu jinde běžných použití OOP zde totiž skvěle nahradí moduly.

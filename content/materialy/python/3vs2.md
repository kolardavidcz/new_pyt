## Historický přechod: Python 3.x vs. Python 2.x

Python je klasickým příkladem jazyka, který se stal **obětí vlastního úspěchu**.

Když v roce 2000 vyšel Python 2.0, Unicode byl do jazyka přidán dodatečně. V následujících letech popularita Pythonu raketově vzrostla a začaly se naplno projevovat architektonické kompromisy 90. let:
- Dvojkolejnost textových a bajtových řetězců vedla k neustálým chybám `UnicodeDecodeError`.
- Spousta vestavěných funkcí vracela objemné seznamy místo líných iterátorů.
- Řada historických reliktů (příkaz `print`, nebezpečný `input()`, operátor `<>`) zbytečně zatěžovala syntaxi.

Guido van Rossum (BDFL) a jádrový tým učinili odvážné rozhodnutí: **provést řízený rozchod se zpětnou kompatibilitou** a vytvořit **Python 3.0** (vydán v prosinci 2008). Výsledkem je konzistentní, moderní a bezpečný jazyk.

<!-- slide: id=id2 title="Poznámka k Python'u 2.7" tags="Core" diff="paradigm" -->
## Poznámka k řadě Python 2.7 a její definitivní konec

Aby byl přechod na Python 3 pro ekosystém (knihovny NumPy, Django, Twisted) snesitelný, vydala komunita verzi **Python 2.7**, do které zpětně naportovala řadu trojkových novinek (např. slovníkové generátory, `unittest2`, `memoryview`).

> [!IMPORTANT]
> **Oficiální konec životního cyklu (EOL)**:
> Podpora Pythonu 2 byla po dvaceti letech definitivně **ukončena 1. ledna 2020**. Dnes je vývoj v Pythonu 2 již minulostí a veškerý kód i nová výuka staví výhradně na **Pythonu 3.12+ / 3.13+**.

## Čtyři pilíře trojkové revoluce

Kdybychom měli nejvýznamnější změny shrnout do čtyř bodů:

1. **`print()` je funkce**:
   - Python 3: `print("Ahoj, světe!")`
   - Python 2: `print "Ahoj, světe!"` (klíčové slovo / příkaz)
2. **Text je striktně Unicode**:
   - Python 3: `"Ahoj"` je plnohodnotný Unicode text (`str`), binární data jsou `b"Ahoj"` (`bytes`).
   - Python 2: `"Ahoj"` byl 8bitový bajtový řetězec, pro Unicode se muselo psát `u"Ahoj"`.
3. **Iterátory jsou všude**:
   - `range()`, `zip()`, `map()`, `filter()`, `dict.keys()` jsou v Pythonu 3 líně vyhodnocované iterátory s paměťovou náročností $O(1)$.
4. **Úklid a reorganizace standardní knihovny**:
   - Sloučení roztříštěných modulů (např. `urllib`, `urllib2`, `urlparse` sloučeny do `urllib.parse` a `urllib.request`).

<!-- slide: id=id4 title="Kódování řetězců" tags="WOW" diff="paradigm" -->
## Práce s řetězci: Text vs. Bajty

Nejfundamentálnější změnou Pythonu 3 je striktní oddělení lidského textu a binárních dat:

### V Pythonu 3.x:
- **`str`**: Sekvence Unicode znaků (abstraktní text bez ohledu na kódování).
- **`bytes`**: Neměnná sekvence surových 8bitových bajtů (`0` až `255`).
- Spojení `str + bytes` vyvolá okamžitou `TypeError`.

### V Pythonu 2.x:
- **`str`**: 8bitový bajtový řetězec.
- **`unicode`**: Znakový řetězec (`u"..."`).
- Interpret se při operaci `str + unicode` pokusil bajtový řetězec **implicitně dekódovat pomocí ASCII**. Pokud řetězec obsahoval jakýkoliv český znak (např. `ě`, `š`, `č`), program havaroval za běhu!

## Kódování zdrojových souborů (`.py`)

- **Python 3**: Výchozím kódováním všech zdrojových souborů je **UTF-8**. Znaky s diakritikou, řecká písmena i emotikony můžete psát přímo do kódu bez jakékoliv hlavičky.
- **Python 2**: Výchozí kódování bylo striktně **ASCII** (nebo závislé na systémovém nastavení Windows/Linux). Pokud soubor obsahoval jediný znak mimo ASCII a chyběl komentář `# -*- coding: utf-8 -*-`, interpret odmítl skript spustit se `SyntaxError: Non-ASCII character`.

<!-- slide: id=id6 title="Kódování řetězců – Py2k" tags="Tricky" diff="newconcept" -->
## Past implicitního přetypování v Pythonu 2

Ukázka zákeřného chování v Pythonu 2:

```python
# Python 2.x:
s_ascii = "ahoj "
s_uni = u"světe"
print s_ascii + s_uni  # u'ahoj světe' (funguje, protože 'ahoj ' je čisté ASCII)

s_cz = "příliš "
# print s_cz + s_uni
# UnicodeDecodeError: 'ascii' codec can't decode byte 0xc5 in position 1!
```

Tato implicitní konverze způsobovala, že programy v testovacím prostředí s anglickými daty fungovaly bezchybně, ale na ostrém produkčním serveru s reálnými jmény uživatelů okamžitě padaly.

V Pythonu 3 je převod mezi `str` a `bytes` **vždy explicitní**: `text.encode("utf-8")` a `raw_bytes.decode("utf-8")`.

<!-- slide: id=id7 title="Názvy souborů" tags="Tricky" diff="newconcept" -->
## Názvy souborů a PEP 383 (`surrogateescape`)

V UNIXových systémech (Linux, BSD) je název souboru na disku definován jako libovolná sekvence bajtů (vyjma `\0` a `/`), která nemusí odpovídat žádnému platnému UTF-8 kódování.

Aby Python 3 dokázal pracovat i s poškozenými nebo nestandardně kódovanými názvy souborů, zavedl **PEP 383**: chybový handler **`surrogateescape`**:
- Neplatné bajty jsou namapovány do vyhrazené oblasti Unicode náhradních kódů (*Surrogate Area* $U+DC80$ až $U+DCFF$).
- To umožňuje soubor otevřít, přejmenovat a beze ztráty informace zapsat zpět na disk.

<!-- slide: id=id8 title="PS – textové soubory" tags="WOW" diff="pythonic" -->
## Otevírání souborů: `open()` a parametr `encoding`

V Pythonu 3 má vestavěná funkce `open()` přímý parametr `encoding`:

```python
# Moderní Python 3:
with open("data.txt", "r", encoding="utf-8") as f:
    obsah = f.read()  # Vrátí str (Unicode)
```

V Pythonu 2 funkce `open()` pracovala pouze s bajty. Pro čtení textu v Unicodu bylo nutné importovat modul `codecs.open()`.

> [!TIP]
> Vždy explicitně uvádějte `encoding="utf-8"`, abyste se vyhnuli závislosti na výchozím kódování operačního systému (např. Windows `cp1250`). V Pythonu 3.15 bude UTF-8 výchozím režimem globálně (PEP 686).

## Sjednocení celých čísel: Konec typu `long`

V Pythonu 2 existovaly dva různé celočíselné typy:
- **`int`**: 32bitové nebo 64bitové číslo s pevnou délkou (omezeno hodnotou `sys.maxint`).
- **`long`**: libovolně velká čísla zapisovaná s příponou `L` (např. `100000000000000000000L`).

**V Pythonu 3 byl typ `long` zrušen a sjednocen pod `int`**:
```python
# V Pythonu 3 má int neomezenou přesnost (arbitrary precision) automaticky:
velke_cislo = 10**100  # Googol – žádné 'L' na konci
print(type(velke_cislo))  # <class 'int'>
```

<!-- slide: id=id10 title="Dělení" tags="Tricky" diff="resyntax" -->
## Změna sémantiky operátoru dělení `/`

Jedna z nejčastějších začátečnických pastí Pythonu 2:

```python
# Python 2.x:
1 / 2      # Vrátilo 0! (Celočíselné dělení, protože oba operandy jsou int)
1.0 / 2    # Vrátilo 0.5
```

### V Pythonu 3.x:
- **`/` (reálné dělení)**: Vždy vrací desetinné číslo `float`:
  ```python
  print(1 / 2)    # 0.5
  print(4 / 2)    # 2.0
  ```
- **`//` (celočíselné dělení)**: Explicitní oříznutí na celé číslo dolů (*floor division*):
  ```python
  print(1 // 2)   # 0
  print(7 // 3)   # 2
  ```

## Bezpečný zápis osmičkových čísel

V Pythonu 2 se osmičková čísla zapisovala s úvodní nulou: `0755` (podle vzoru jazyka C). To vedlo k nebezpečným chybám, kdy číslo `010` znamenalo dekadických 8!

V Pythonu 3 byl sjednocen prefix pro všechny číselné soustavy:
- **Šestnáctková (Hex)**: `0x41` (dec 65)
- **Osmičková (Oct)**: **`0o101`** (dec 65, původní `0101` je v Pythonu 3 syntaktická chyba)
- **Dvojková (Bin)**: `0b1000001` (dec 65)

<!-- slide: id=id12 title="Iterátory – „range“" tags="WOW" diff="pythonic" -->
## Paměťová efektivita: `range()` vs. `xrange()`

- **V Pythonu 2**: funkce `range(1_000_000)` okamžitě alokovala v paměti seznam s milionem celočíselných objektů. Pro línou iteraci se musela volat speciální funkce `xrange()`.
- **V Pythonu 3**: funkce `range()` je **líně generovaný rozsah**:
  ```python
  r = range(1_000_000_000)  # Nezabírá žádnou paměť (pouze start, stop, step)
  print(r)                  # range(0, 1000000000)
  print(100 in r)           # True (okamžité O(1) vyhodnocení bez procházení!)
  ```
Funkce `xrange()` byla v Pythonu 3 jako redundantní odstraněna.

---
<!-- slide: id=id13 title="Iterátory – slovníky" tags="Core" diff="pythonic" -->
## Dynamické pohledy na slovníky (Dictionary Views)

V Pythonu 2 vracely metody `keys()`, `values()` a `items()` nezávislé statické kopie v podobě seznamů.

V Pythonu 3 vrací **dynamické pohledy** (*views*):
```python
d = {"a": 1, "b": 2}

klice = d.keys()      # dict_keys(['a', 'b'])
d["c"] = 3
print(klice)          # dict_keys(['a', 'b', 'c']) -> změna se okamžitě projevila!
```

Pohledy na klíče a položky navíc podporují množinové operace (`&`, `|`, `-`):
```python
spolecne_klice = dict1.keys() & dict2.keys()
```

Zastaralé metody `iterkeys()`, `itervalues()`, `iteritems()` byly odstraněny.

<!-- slide: id=id14 title="Iterátory – „zip“" tags="Core" diff="pythonic" -->
## Líné párování: `zip()`

Podobně jako `range`, i funkce **`zip()`** se v Pythonu 3 stala líným generátorem:

```python
jmena = ["Alice", "Bob", "Cyril"]
body = [100, 85, 92]

z = zip(jmena, body)
print(z)  # <zip object at 0x...>
print(list(z))  # [('Alice', 100), ('Bob', 85), ('Cyril', 92)]
```

V Pythonu 2 funkce vracela rovnou celý seznam a líná varianta se musela importovat jako `itertools.izip()`.

---
<!-- slide: id=id15 title="Iterátory – „map“" tags="Skip" diff="pythonic" -->
## Funkcionální nástroje: `map()`

Funkce `map()` aplikuje zadanou transformaci na prvky sekvence:

```python
mocniny = map(lambda x: x**2, [1, 2, 3, 4])
print(mocniny)  # <map object at 0x...>
print(next(mocniny))  # 1
print(next(mocniny))  # 4
```

Hodnoty se počítají až v okamžiku, kdy si o ně konzument řekne. Zastaralý `itertools.imap()` byl zrušen.

---
<!-- slide: id=id16 title="Iterátory – „filter“" tags="Skip" diff="pythonic" -->
## Funkcionální filtrace: `filter()`

Stejná změna potkala i funkci `filter()`:

```python
suda = filter(lambda x: x % 2 == 0, range(10))
print(suda)        # <filter object at 0x...>
print(list(suda))  # [0, 2, 4, 6, 8]
```

V Pythonu 2 vracel `filter()` buď seznam, nebo řetězec podle typu vstupu. V Pythonu 3 je návratový typ vždy univerzální líný generátor.

<!-- slide: id=id17 title="Iterátory – „next()“ a „__next__()“" tags="WOW" diff="paradigm" -->
## Protokol iterátoru: Magická metoda `__next__()`

V Pythonu 2 měl iterátor pro posun na další prvek běžnou metodu `it.next()`. To bylo v rozporu se standardem jazyka, kde interní protokoly používají magické dunder metody.

### V Pythonu 3:
- Objekt iterátoru implementuje **`__next__()`**.
- V uživatelském kódu se volá vestavěná funkce **`next(it)`** (případně s výchozí hodnotou `next(it, default)`):

```python
it = iter([10, 20])
print(next(it))       # 10
print(next(it))       # 20
print(next(it, -1))   # -1 (místo vyvolání StopIteration)
```

<!-- slide: id=id18 title="Generátorová notace" tags="WOW" diff="pythonic" -->
## Množinové a slovníkové generátory (Comprehensions)

Python 3 zavedl přímou syntaktickou podporu pro generování množin a slovníků:

```python
# 1. Seznamový generátor (List comprehension)
ctverce = [x**2 for x in range(5)]

# 2. Množinový generátor (Set comprehension)
unikatni = {x.lower() for x in ["A", "b", "A", "C"]}  # {'a', 'b', 'c'}

# 3. Slovníkový generátor (Dict comprehension)
mapa = {k: k**2 for k in range(4)}  # {0: 0, 1: 1, 2: 4, 3: 9}
```

V raném Pythonu 2 šlo tímto zápisem vytvářet pouze seznamy.

## Zrušení zastaralého operátoru `<>`

V Pythonu 2 existoval vedle standardního `!=` také alternativní operátor nerovnosti `<>` (převzatý z Pascalu a BASICu).

V Pythonu 3 byl operátor `<>` kompletně odstraněn. Jediným platným operátorem pro test nerovnosti je **`!=`**.

<!-- slide: id=id20 title="Porovnávání hodnot" tags="Tricky" diff="newconcept" -->
## Striktní typové porovnávání

V Pythonu 2 bylo možné vzájemně porovnávat hodnoty zcela nekompatibilních typů:

```python
# Python 2.x (absurdní chování):
2 < "1"       # True! (Číslo bylo vždy menší než řetězec na základě názvů typů)
None < 0      # True!
```

### V Pythonu 3:
Porovnání nekompatibilních typů vyvolá **`TypeError`**:
```pycon
>>> 2 < "1"
TypeError: '<' not supported between instances of 'int' and 'str'
```

Tato změna zabraňuje tichým chybám při řazení seznamů obsahujících neočekávané smíšené typy.

<!-- slide: id=id21 title="Řazení objektů" tags="WOW" diff="pythonic" -->
## Moderní řazení: parametr `key`

V Pythonu 2 používalo řazení historický parametr `cmp=funkce(a, b)`, který vracel `-1, 0, 1`. To vyžadovalo $O(N \log N)$ volání funkce.

V Pythonu 3 byl parametr `cmp` zrušen a jediným podporovaným způsobem je **transformační funkce `key=`**:

```python
studenti = [("Jana", 90), ("Petr", 75), ("Eva", 98)]

# Řazení podle bodů (druhý prvek n-tice):
serazeno = sorted(studenti, key=lambda s: s[1], reverse=True)
```

Hodnota klíče se pro každý prvek spočítá pouze jednou ($O(N)$), což je řádově rychlejší.

<!-- slide: id=id22 title="„True + True“" tags="Already Studied" diff="paradigm" -->
## Rezervovaná klíčová slova `True` a `False`

V Pythonu 2 byly konstanty `True` a `False` pouhými globálními proměnnými, které bylo možné přepsat:

```python
# Python 2.x (katastrofální možnost přepsání):
True = False  # Zcela legální v Pythonu 2.4 a starším!
```

V Pythonu 3 jsou **`True`**, **`False`** a **`None`** plnohodnotnými **klíčovými slovy jazyka**. Pokus o přiřazení skončí okamžitou chybou `SyntaxError: cannot assign to True`.

<!-- slide: id=id23 title="Bublání ven proměnných generátorové notace" tags="Already Studied" diff="newconcept" -->
## Izolace jmenného prostoru v generátorech

V Pythonu 2 řídicí proměnná seznamového generátoru přepisovala proměnnou ve vnějším rozsahu platnosti:

```python
# Python 2.x:
x = "globální"
seznam = [x for x in range(3)]
print x  # Vypsalo 2! Původní hodnota byla přepsána!
```

### V Pythonu 3:
Generátory mají svůj vlastní lokální jmenný prostor (*scope*), takže proměnné zevnitř nikdy neprosakují ven:
```python
x = "globální"
seznam = [x for x in range(3)]
print(x)  # 'globální' (zůstalo nedotčeno)
```

<!-- slide: id=id24 title="„print()“ vs „print“" tags="Core" diff="resyntax" -->
## Změna `print` na funkci

Převod `print` na funkci umožnil předávat volitelné pojmenované argumenty:

| Vlastnost | Python 3 (`print()`) | Python 2 (`print`) |
| :--- | :--- | :--- |
| **Základní výpis** | `print("Ahoj")` | `print "Ahoj"` |
| **Bez nového řádku** | `print(x, end="")` | `print x,` |
| **Oddělovač prvků** | `print(a, b, sep=", ")` | nutné ruční formátování |
| **Přesměrování do souboru** | `print(err, file=sys.stderr)` | `print >>sys.stderr, err` |
| **Okamžité vyprázdnění bufferu** | `print(msg, flush=True)` | nutné `sys.stdout.flush()` |

Jako funkci lze `print` snadno předávat jako callback nebo přepsat v rámci testů.

## Bezpečnost: `input()` vs. `raw_input()`

Jedna z nejnebezpečnějších vlastností Pythonu 2:
- **`input()` v Pythonu 2**: Automaticky vyhodnotil zadaný text jako pythonní výraz funkcí `eval()`! Pokud uživatel zadal `__import__('os').system('rm -rf /')`, příkaz se vykonal!
- **`raw_input()` v Pythonu 2**: Načetl vstup bezpečně jako čistý řetězec.

### V Pythonu 3:
Původní nebezpečný `input()` byl smazán a bezpečný `raw_input()` byl **přejmenován na `input()`**:
```python
jmeno = input("Zadejte jméno: ")  # Vždy bezpečný textový řetězec str
```

## Odstranění zpětných apostrofů (Backticks)

V Pythonu 2 šlo místo volání `repr(objekt)` použít zápis se zpětnými apostrofy: `` `objekt` ``.

V Pythonu 3 byly zpětné apostrofy zrušeny pro nepřehlednost a snadnou záměnu s běžnými uvozovkami či apostrofy. Používá se výhradně **`repr()`**.

<!-- slide: id=id27 title="Výjimky – „except“" tags="Core" diff="resyntax" -->
## Odchytávání výjimek: syntaxe `as`

V Pythonu 2 se zachycená výjimka ukládala za čárku:
```python
# Python 2.x:
try:
    krok()
except ValueError, e:  # Čárka!
    pass

# Pozor na nebezpečnou záměnu:
# except TypeError, ValueError:  # V Pythonu 2 to zachytilo POUZE TypeError a uložilo jej do proměnné ValueError!
```

### V Pythonu 3:
Používá se explicitní klíčové slovo **`as`**:
```python
try:
    krok()
except ValueError as e:
    print("Chyba:", e)
except (TypeError, KeyError) as e:  # Více výjimek v n-tici
    print("Chyba typu nebo klíče:", e)
```

<!-- slide: id=id28 title="Výjimky – „raise“ a řetězení" tags="Skip" diff="resyntax" -->
## Vyvolávání výjimek a Exception Chaining

V Pythonu 3 se výjimky vyvolávají jako instance:
```python
raise ValueError("Neplatná hodnota")  # Jediná platná syntaxe
```

### Řetězení výjimek (*Exception Chaining* v Pythonu 3):
Pomocí klíčového slova `from` můžeme zachovat původní příčinu chyby:
```python
try:
    nacist_konfiguraci()
except FileNotFoundError as err:
    raise RuntimeError("Aplikace nemůže nastartovat") from err
```
Při výpisu chyby Python automaticky zobrazí oba trasovací protokoly (*tracebacky*).

## Deklarace metatříd

- **V Pythonu 2**: Metatřída se definovala magickým atributem uvnitř těla třídy:
  ```python
  class MojeTrida(object):

  ```
- **V Pythonu 3**: Metatřída se předává jako pojmenovaný argument v hlavičce třídy:
  ```python
  class MojeTrida(metaclass=Meta):

  ```

<!-- slide: id=id30 title="„super()“" tags="WOW" diff="pythonic" -->
## Zjednodušené volání `super()`

V Pythonu 2 vyžadovalo volání rodičovské metody opakování názvu třídy i instance:
```python
# Python 2.x (upovídané a náchylné k chybám při přejmenování třídy):
class Potomek(Rodic):
    def __init__(self, x):
        super(Potomek, self).__init__(x)
```

### V Pythonu 3 (čisté volání bez parametrů):
```python
class Potomek(Rodic):
    def __init__(self, x):
        super().__init__(x)  # Python si třídu i instanci dosadí sám!
```

## Souhrn: Dědictví přechodu na Python 3

| Oblast | Python 2.x | Python 3.x (3.12+ / 3.13+) |
| :--- | :--- | :--- |
| **Textový typ** | `str` (8-bit ASCII/bajt) | **`str` (Unicode UTF-8)** |
| **Binární data** | `str` | **`bytes` / `bytearray`** |
| **Výstup** | `print x` (příkaz) | **`print(x)` (funkce)** |
| **Vstup** | `input()` (eval!), `raw_input()` | **`input()` (bezpečný text)** |
| **Dělení** | `1 / 2 == 0` | **`1 / 2 == 0.5`, `1 // 2 == 0`** |
| **Celočíselný typ** | `int`, `long` (s `L`) | **sjednocený `int` (libovolná délka)** |
| **Generátory** | `range()`, `dict.keys()` (seznamy) | **líné iterátory $O(1)$ paměť** |
| **Rodičovská třída** | `super(Cls, self).__init__()` | **`super().__init__()`** |

Přechod na Python 3 položil pevné základy, na kterých dnes staví moderní inovace: statické typování (`typing`), asynchronní programování (`async`/`await`), strukturální pattern matching (`match/case`) a vysoce optimalizovaný interpret.
